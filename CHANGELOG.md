# Changelog

## [Unreleased]

### Added
- Optimistic UI, offline mutation queue, and ETag conflict handling (`PendingMutation`, `IPendingMutationStore`, `SqlitePendingMutationStore`, `IMutationService`, `MutationService`, `IConflictNotifier`, `ConflictNotifier`, `GooglePreconditionFailedException`, FR-SYNC-4, NFR-REL): enables optimistic UI updates by applying event creations, modifications, and deletions immediately to local SQLite storage while enqueuing mutations in the `PendingMutation` table within the same atomic transaction; flushes pending mutations in FIFO order via background sync passes or immediate post-mutation triggers; includes idempotency keys (`ClientRequestId`) and ETag concurrency control (`If-Match: "{etag}"`); catches HTTP 412 Precondition Failed conflicts, dequeues the conflicting mutation, fetches the remote event version from Google Calendar API to overwrite local state (server-wins conflict policy), and dispatches user notifications via `IConflictNotifier`; safely defers and retries queued operations when offline or experiencing transient network faults without losing changes (FR-SYNC-4, NFR-REL, P3-13).
- Hosted background sync scheduler with active and tray polling (`ISyncScheduler`, `SyncScheduler`, `SyncScheduleState`, `SyncOptions`, FR-SYNC-3): manages periodic Google Calendar background synchronization with adaptive polling intervals (2 minutes when the application window is `Active`, 10 minutes when minimized to the system tray or running in the background `TrayOrBackground`, configurable via `SyncOptions.PollingActiveMinutes` and `SyncOptions.PollingTrayMinutes`); supports immediate synchronization triggers on main window focus (`TriggerFocusSyncAsync`), post-write mutations (`TriggerPostMutationSyncAsync`), and manual user "Sync Now" requests (`TriggerManualSyncAsync`); uses concurrency coalescing to prevent overlapping synchronization passes; integrates as a .NET `BackgroundService` and `IHostedService`; verified with deterministic fake clock testing (`IClock`, `FakeClock`) (FR-SYNC-3, P3-12).
- Google quota management and request throttling (`IClock`, `SystemClock`, `SyncOptions`, `ThrottlingDelegatingHandler`, `ResiliencePipelineExtensions`, FR-SYNC-5): enforces outbound request throttling strictly to ≤ 5 requests/second (configurable via `LunarCal:Sync:MaxRequestsPerSecond`) using an `IClock` abstraction with rolling 1-second reservation windows and asynchronous delay; enhances HTTP resilience retry policies to automatically retry with exponential backoff and jitter on Google API rate limit errors (HTTP 429 Too Many Requests and HTTP 403 Forbidden with `rateLimitExceeded`, `userRateLimitExceeded`, or `quotaExceeded`), while preserving idempotency safety guarantees (SEC-NET-2) (FR-SYNC-5, P3-11).
- Incremental synchronization with syncToken and automatic HTTP 410 full resync recovery (`ISyncEngine`, `SyncEngine`, `SyncResult.FullResyncTriggered`, `GoogleCalendarSyncTokenExpiredException`, FR-SYNC-2): executes delta synchronization for stored calendars using persisted `sync_token`; queries Google Calendar API v3 events endpoint with `syncToken` and `singleEvents=true`; applies delta updates by atomically deleting cancelled events (`status: "cancelled"`) from SQLite and upserting new or updated events; detects expired sync tokens (HTTP 410 Gone / `GoogleCalendarSyncTokenExpiredException`) and automatically clears obsolete sync tokens, purges stale cached events, and triggers a clean full resync within the [−12 months, +24 months] window, updating `CalendarInfo.sync_token` with fresh tokens (FR-SYNC-2, P3-10).
- Google Calendar API v3 REST gateway and initial synchronization engine (`ICalendarGateway`, `CalendarGateway`, `ISyncEngine`, `SyncEngine`, `CalendarListResult`, `EventsListResult`, `SyncResult`, `GoogleCalendarSyncTokenExpiredException`, ADR-0028): executes initial synchronization of user Google calendars and events; queries `users/me/calendarList` with `minAccessRole=reader` and `showHidden=false`; computes the event synchronization window of [−12 months, +24 months] relative to current UTC time; queries `calendars/{calendarId}/events` with `singleEvents=true`, expanding recurring event series; captures `nextSyncToken` from the final events page for future incremental synchronization; saves all calendars and events in an atomic SQLite transaction into `CalendarInfo` and `Event` tables, persisting `google_id`, `recurring_event_id`, `start_utc`, `end_utc`, `all_day`, `timezone`, `etag`, `updated`, `status`, and serializing `extendedProperties.private` (including `lunarRuleId`, `createdBy`, `batchId`) into `extended_json` (FR-SYNC-1, FR-SYNC-6, ADR-0028, P3-09).
- Infrastructure HttpClient resilience pipeline and outbound network security (`Microsoft.Extensions.Http.Resilience` 10.2.0, `NetworkSecurityDelegatingHandler`, `NetworkSecurityValidator`, `NetworkOptions`, `HttpIdempotencyHelper`, `ResiliencePipelineExtensions`, `NetworkSecurityException`): enforces strict HTTPS-only transport and allow-listed host verification against `LunarCal:Network:AllowedHosts` (`*.googleapis.com`, `accounts.google.com`, `oauth2.googleapis.com`, `generativelanguage.googleapis.com`, plus dynamic cloud ingestion and update hosts) without bypassing OS certificate validation (SEC-NET-1); configures standard resilience with bounded exponential backoff retries, circuit breaker, attempt and total request timeouts; enforces custom idempotency filtering so write operations (POST, PUT, PATCH, DELETE) lacking a requestId (header `X-Request-Id`, query parameter, or `HttpRequestOptions`) or ETag/If-Match header are NEVER retried upon transient failure (SEC-NET-2, P3-08).
- Google account sign-out and cache wipe service (`IGoogleSignOutService`, `GoogleSignOutService`, `GoogleSignOutResult`, `IGoogleOAuthClient.RevokeTokenAsync`): implements secure account sign-out requiring explicit user confirmation; revokes Google OAuth tokens via Google's token revocation endpoint (`https://oauth2.googleapis.com/revoke`); securely removes encrypted refresh tokens from DPAPI secret storage; purges all account metadata, calendars, cached events, reminder states, and associated lunar rules from local SQLite storage while leaving other accounts intact; ensures local logout succeeds even during offline or network errors; includes localized confirmation strings `auth.signout.confirm_title`, `auth.signout.confirm_message`, and `auth.signout.confirm_action` in vi-VN and en-US (FR-AUTH-4, SEC-OAUTH-3, P3-07).
- Automated Google OAuth 2.0 access token refresh and invalid grant handling (`IGoogleOAuthClient`, `GoogleOAuthClient`, `GoogleInvalidGrantException`, `GoogleTokenRefreshResult`, `GoogleOAuthOptions`): executes token refresh with stored DPAPI refresh tokens (`KnownSecretKeys.GoogleRefreshToken`); safely updates encrypted DPAPI secret storage when Google rotates refresh tokens; detects Google `invalid_grant` errors (expired or revoked tokens) and immediately purges dead tokens from DPAPI storage to prevent repeated failed attempts; raises structured `GoogleInvalidGrantException` or non-throwing `GoogleTokenRefreshResult` with clear user guidance including the 7-day token expiration warning when the OAuth consent screen is configured in Testing mode; includes localized strings `auth.reauth.required` and `auth.reauth.testing_notice` across `vi-VN` and `en-US` (FR-AUTH-3, FR-AUTH-6, ADR-0026, P3-06).
- Google OAuth 2.0 desktop authentication with PKCE S256 (`IGoogleOAuthClient`, `GoogleOAuthClient`, `PkceParameters`, `OAuthState`, `LoopbackHttpListener`, `LoopbackHttpListenerFactory`, `GoogleOAuthOptions`, `GoogleOAuthScopes`, `GoogleUserInfoParser`, `ISystemBrowser`, `SystemBrowser`): implements RFC 8252 and RFC 7636 authorization code flow with S256 code challenge; binds loopback redirect strictly to `127.0.0.1` on a dynamic port with a 5-minute timeout and closes the listener immediately upon callback or timeout (SEC-OAUTH-1); validates cryptographic `state` in constant time to prevent CSRF attacks; opens the system default browser without embedded WebViews (FR-AUTH-1); requests least-privilege scopes (`calendar.events`, `calendar.readonly`, `openid`, `email`, `profile`) (FR-AUTH-2, SEC-OAUTH-2); resolves OAuth Client ID from build configuration and user-secrets with user override fallback (FR-AUTH-6); securely parses user profile from ID tokens and stores refresh tokens encrypted in DPAPI `ISecretStore` under `KnownSecretKeys.GoogleRefreshToken` (SEC-OAUTH-3, FR-AUTH-3, ADR-0017, P3-05).
- Local data security and full data wipe service (`LocalStorageDirectorySecurity`, `ILocalDataWipeService`, `LocalDataWipeService`, `LocalDataWipeOptions`): enforces Windows directory Access Control Lists (ACLs) on `%LOCALAPPDATA%/LunarCal/` and child directories to restrict access strictly to the current Windows user (`FileSystemRights.FullControl`) with inheritance disabled; provides comprehensive local data wiping (SEC-DATA-3) that clears DPAPI credentials/keys, releases SQLite connection pools, deletes SQLite database files (`.db`, `.db-wal`, `.db-shm`), recursively purges the data lake outbox, cleans cached files, and restores directory security (SEC-DATA-2, SEC-DATA-3, P3-04).
- Local encrypted SQLite storage using SQLCipher (`Microsoft.Data.Sqlite.Core` 10.0.14 and `SQLitePCLRaw.bundle_e_sqlcipher` 2.1.11, `ISqliteConnectionFactory`, `SqliteConnectionFactory`, `SqliteStorageOptions`): securely wraps a 256-bit database key generated at first launch in DPAPI `ISecretStore` (`KnownSecretKeys.DatabaseKey`); validates encryption so database cannot be opened without key or with wrong key; safely refuses to open existing database if key is missing; enforces foreign keys; manages versioned migrations (`ISqliteMigration`, `SqliteMigrationRunner`) creating the full 9-table schema and indexes (`Account`, `CalendarInfo`, `Event`, `LunarRule`, `PendingMutation`, `AppSetting`, `AiCommand`, `ContributionOutbox`, `ReminderState`) and preserving existing data across upgrades (SEC-DATA-1, spec §6, NFR-REL, ADR-0013, P3-03).
- Windows DPAPI encrypted secret storage (`ISecretStore`, `DpapiSecretStore`, `DpapiSecretStoreOptions`, `KnownSecretKeys`): encrypts secrets at rest using DPAPI `CurrentUser` scope with app-specific entropy; supports string and raw byte secrets, atomic writes via temp file replacement, thread-safe access, round-trip retrieval, and deletion; verifies stored ciphertext contains zero plaintext secret or key data (SEC-KEY-1, SEC-OAUTH-3, FR-AUTH-3, ADR-0018, P3-02).
- Serilog file logging infrastructure with 14-day daily rotation, Information default level, and comprehensive redaction: `LogRedactor` (masking Gemini API key, Google OAuth access token, Bearer/Authorization headers, refresh tokens, client secrets, optional email masking), `RedactingEnricher`, `RedactingDestructuringPolicy` (sanitizing sensitive event fields like title, summary, location, description per FR-NOTIFY-9), and `RedactingTextFormatter` (SEC-LOG-1, SEC-LOG-2, ADR-0019, P3-01).
