# Changelog

## [Unreleased]

### Changed
- One Google account at a time (FR-AUTH-5, ADR-0029, P4-R2): every sign-in (first run, Settings, re-login) goes through `IAccountSessionService`. Signing in with a different Google account shows the "Switch Google account?" confirmation (Figma S14 1.5) and, if confirmed, deletes the old tokens and every local table of the old account before loading the new one; the same account keeps everything. Settings > Advanced (S20) shows a single account with "Change account…".

### Fixed
- AI progress card (P4-R7, Figma 4.5): the failed and done states were drawn in the purple "working" colours and the close icon of the card and of the offline banner rendered as a dot; fixed after comparing the WPF render with the new Figma frame.
- AI command times (FR-QUEUE-4, FR-CONFIRM-1, ADR-0032, P4-R5): `typed_at` came back from storage as UTC, so "6h tối mai" was shown as 11:00 and the prompt used UTC dates. It is now restored to the command's own time zone, the prompt carries local time with an explicit UTC offset, the dialog shows local time and Vietnamese weekday names, and confirmed all-day events fall back to the command's zone instead of the machine zone.
- AI requests took minutes (FR-QUEUE-5, ADR-0032, P4-R6): Gemini is called with thinking level `low` (dropped automatically if the API rejects it) and a 4096 token budget, every call logs its duration and token counts (never content), and queue retries start at 5 seconds (5 s, 30 s, 3 min, 18 min) instead of 1 minute.
- AI queue drawer (FR-QUEUE-6, P4-R7): it closes when "Xem" or "Xác nhận" is pressed, follows the worker while open, shows a translated error instead of raw English text wrapped in `!`, shows the real retry wait, and "Xem" on a command that is no longer waiting keeps Confirm locked.
- AI commands now work end to end (FR-CHAT-1, FR-CHAT-2, FR-CHAT-4, FR-QUEUE-2, FR-CONFIRM-6, FR-CONFIRM-8, ADR-0031, P4-REVIEW): the chat orchestrator and a calendar tool executor (`create_event`) are registered, the model's proposal is stored on the queued command (migration V4 `AiCommand.proposal_json`), the confirmation dialog shows that proposal instead of a made-up one, and the calendar is only written after the user presses Confirm. Before, "Confirm" only marked the command completed and no event was created; the queue worker also spun in a tight loop when no orchestrator was available.
- The confirmation validator, confidence score and dialog read the tool fields the model actually returns (`title`, `allDay`, `eventId`); a real proposal was reported as "title missing" and Confirm stayed locked (FR-CONFIRM-1, FR-CONFIRM-4).
- Chat text is no longer logged at the default level and the raw Gemini response of a failed function-calling probe is never logged (SEC-LOG-2).
- AI confirmation dialog rebuilt to match Figma 02: AI tile, status chip, plain action text, confidence chip, validation icon, privacy note and purple primary button (FR-CONFIRM-1, FR-UI-11).
- Signing out of Google (FR-AUTH-4) left `PendingMutation` and `AiCommand` rows behind, so queued changes of the old account could be replayed against the next account; they are deleted now.
- Event editor (Figma S10, P3-R2, FR-UI-4, FR-LUNAR-5): dialog rebuilt from the design; reminders and solar repeat are now saved (they were dropped), the editor loads the user's calendars and refuses to save without one instead of writing to a non-existent "primary" calendar, a lunar rule keeps its `lunarRuleId` across saves, and a test checks every `{loc:Loc}` key in XAML exists in vi-VN and en-US.
- UI smoke test `Settings_button_opens_appearance_page` no longer fails with `NoClickablePointException` (selects the nav item through UI Automation).
